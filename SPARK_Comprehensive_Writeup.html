1. Why We Built SPARK & The Problems It Solves

Modern high-velocity engineering, design, and product teams face severe communication fragmentation. Team context is scattered across chaotic instant messaging channels, isolated task trackers, and unencrypted third-party file drops. Furthermore, standard team messaging platforms either force teams into rigid, bloated proprietary interfaces or lack genuine client-side zero-knowledge security.

SPARK solves this by synthesizing real-time channel communication, direct peer messaging, task-driven workflow handovers, and zero-knowledge encrypted media sharing into one coherent, lightning-fast workspace. Powered by the Nexconn Chat SDK (`@nexconn/chat@26.2.1`), SPARK delivers sub-second message delivery and live presence indicators while ensuring enterprise-grade AES-256 data protection and AI-assisted channel catch-ups.

2. Nexconn Chat SDK Deep Dive

SPARK is built directly on the core @nexconn/chat@26.2.1 SDK, deliberately pairing Nexconn's robust event-driven real-time infrastructure with a custom-engineered Next.js 16 / React 19 UI tailored to developer workflows:

🚀 Real-Time Channel Messaging

Subscribes to channel topics (e.g., #general) via Nexconn's real-time connection engine. Messages dispatch bidirectionally with sub-second propagation across all authenticated workspace members.

🔒 Direct 1-on-1 Workspace Chat

Enables private peer dialogues utilizing Nexconn SDK ConversationType.PRIVATE. Messages, read confirmations, and active states synchronize instantaneously across distinct user accounts.

🟢 Live Online Presence Tracking

Integrates Nexconn presence hooks (watchPresence) combined with an automated heartbeat mechanism and window visibility detection (focus, visibilitychange) to show active status rings in real time.

⚡ Resilient Sub-Second Hydration

Engineered a hybrid architectural pipeline: instant database cache hydration renders past channel logs in under 150ms, while the Nexconn SDK simultaneously initiates socket channels asynchronously without blocking UI rendering.

3. Section-by-Section Feature Breakdown & How to Use

3.1 Chat System & Real-Time Messaging (`/chat`)

  • Channel Communication: Browse public and private workspace channels (e.g., #general, #engineering). Members can participate in open discussions, post code snippets, and format text with Markdown.
  • Direct Messages (DMs): Secure 1:1 messaging channels with team members. Clicking any member in the sidebar instantly initiates a private conversation stream.
  • Sub-Second Loading: Messages load in under 150 milliseconds from PostgreSQL cache, while Nexconn real-time listeners hydrate incoming messages on the fly.
  • Delivery Receipts: Real-time message status indicators (sending spinner, delivered checkmarks, failed notification with retry option).

3.2 Live Online Presence & Activity Tracking

  • Dynamic Emerald Badges: Active teammates display a vibrant green status badge on their avatar ring.
  • Tab & Focus Detection: The presence system automatically listens to window focus, pageshow, and visibilitychange events to track when teammates are actively engaging with the workspace.
  • Heartbeat Engine: A low-overhead 20-second heartbeat keeps session states synchronized across distributed clients.

3.3 Client-Side Zero-Knowledge AES-256-GCM Media Encryption

  • Zero Plaintext Storage: Media files and screenshots are encrypted entirely inside the client's browser before network transmission.
  • Cryptographic Specifications: Uses Web Cryptography API (crypto.subtle) with 256-bit AES-GCM symmetric keys and unique 12-byte initialization vectors (IVs).
  • Secure Media Delivery: The server only ever sees encrypted ciphertext stored in PostgreSQL (chat_encrypted_media). Only authorized conversation participants receive the decryption key to construct memory-safe local Blob URLs.

3.4 AI-Powered Channel "Catch Up" Engine

  • Contextual Thread Synthesis: Clicking the Catch Up button in the chat header triggers an AI agent that analyzes the recent message backlog.
  • Actionable Synthesis: Categorizes long discussions into Key Decisions Reached, Assigned Action Items, and Technical Blockers, allowing engineers returning from meetings or breaks to catch up in 10 seconds.
  • Quick Replies: Context-aware response chips dynamically suggest one-click replies above the message composer.

3.5 Integrated Task Management & Kanban Board (`/tasks`)

  • Interactive Kanban Board: Full agile task board with To Do, In Progress, In Review, and Done columns.
  • Conversation-to-Task Handover: The Handover pill next to the chat input allows any team member to convert an active chat discussion into an actionable task with assignees, priorities, and deadlines in a single click.
  • Task Drawer Details: Granular task cards supporting priority tags (Low, Medium, High, Urgent), due dates, and real-time state updates.

3.6 Workspace Isolation, Roles & Organizations (`/workspaces`)

  • Multi-Tenant Workspace Engine: Teams operate inside dedicated workspaces isolated by unique slugs (e.g., /workspaces/test).
  • Role-Based Access Control (RBAC): Granular permissions separating Admins, Members, and Guests.
  • Team Management: Invite colleagues via secure email tokens or direct workspace links.

4. End-to-End User & Team Workflows

Workflow 1: Instant Onboarding & Channel Entry

  1. The user navigates to /auth/login and enters their credentials (or signs up via /auth/signup).
  2. Upon authentication, the workspace bootstrap queries the user's active organizations and establishes a scoped Nexconn session token via /api/chat/token.
  3. The user is brought directly into the Test workspace and `#general` channel.
  4. The presence engine broadcasts their online status to all workspace members in real time.

Workflow 2: The Chat-to-Task Execution Loop

  1. Teammates discuss a product requirement or bug in #general.
  2. A team member clicks the Handover button in the chat input toolbar.
  3. A task modal appears, automatically pre-filling with the relevant discussion context.
  4. The creator assigns the task to a teammate and sets the priority to High.
  5. The task appears immediately on the Kanban board (/tasks), and a confirmation event is broadcast to the team.

Workflow 3: Zero-Knowledge Encrypted Media Transmission

  1. The user clicks the attachment icon in the chat composer and selects a sensitive document or screenshot.
  2. The client browser generates an AES-256-GCM cryptographic key and encrypts the file before upload.
  3. The encrypted binary is persisted in PostgreSQL, and the metadata payload is broadcast via Nexconn Chat SDK.
  4. The recipient's browser receives the payload, verifies conversation membership, decrypts the ciphertext in memory, and renders the media seamlessly.
